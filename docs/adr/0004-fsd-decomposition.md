# 0004 · Раскладка фронтенда по FSD

- **Статус:** proposed
- **Дата:** 2026-08-12
- **Ответственные:** —
- **Связанные ASR:** ASR-3 (изменяемость), ASR-4 (единый транспортный контракт)

## Контекст и постановка проблемы

Сейчас логика задачи размазана: каждый консьюмер (~490 строк) сам держит UI, опрос, retry и
персистентность, а чат — ещё и отдельный движок. Границ нет, поэтому правка одного места
задевает соседнее, а новый тип задачи копируется целиком. Нужен способ организации кода,
где домен, транспорт и UI разнесены и не ходят друг к другу как попало.

## Драйверы решения

- Новый тип задачи должен подключаться без правки ядра (ASR-3).
- Домен не должен зависеть от транспорта (ASR-4, DIP из [04-decomposition](../04-decomposition.md)).
- Границы должны проверяться автоматически, а не только на ревью.

## Рассмотренные варианты

**A. Feature-Sliced Design.** Слои `app → pages → widgets → features → entities → shared`,
зависимости только вниз, наружу — публичный API слайса. Границы проверяет линтер.

**B. Группировка по техническим папкам** (`components`, `hooks`, `services`, `utils`).
Привычно, но границы «по типу файла», а не «по причине изменения» — то, от чего уходим.

**C. Оставить как есть** — модули-консьюмеры без общей структуры.

## Решение

Берём вариант A. FSD даёт понятные слои и правило зависимостей, ложится на уже описанную
модель: `entities/task` = Task Orchestrator и порт, `shared/api` = адаптеры транспорта,
`entities/task-type` = типы задач, `widgets/task-feed` = проекция для пользователя.

### Последствия

- Домен (стейт-машина, порт) изолирован от транспорта и UI; правки локальны.
- Новый тип задачи = новый слайс/конфиг, ядро не трогаем (ASR-3).
- Появляется дисциплина публичных API и запрет импортов в обход слоёв — её надо
  поддерживать линтером границ, иначе структура со временем «поплывёт».
- Слой `pages` у нас почти пустой (модуль встраивается в чужие страницы) — это нормально,
  не заполняем его ради полноты.

## Плюсы и минусы вариантов

**A — FSD.** Явные границы по причине изменения, автоматическая проверка, прямое
соответствие декомпозиции. Взамен — начальная дисциплина и накладные расходы на публичные API.

**B — папки по типам.** Ничего не надо объяснять команде, но границы формальные: домен и
инфраструктура всё равно перемешиваются.

**C — как есть.** Нулевая стоимость сегодня и та самая боль сопровождения завтра.
