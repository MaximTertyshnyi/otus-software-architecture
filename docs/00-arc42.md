# 00 · Обзор документации: Arc42, C4 и принцип достаточности

## Принцип «достаточно для коммуникации»

Документация — средство коммуникации, а не самоцель. Пишем ровно столько, чтобы
новый человек понял: **зачем** система, **какие качества** важны, **как** она устроена
крупно и **почему** приняты ключевые решения. Не документируем то, что и так видно в
коде. Живые артефакты проекта: ASR, C4 (обзорно), ADR (решения) — остальное только
по необходимости.

## C4 — обзорно

Ведём **обзорный уровень**:

- **L1 Context** и **L2 Containers** — основной обзор системы ([c4/](c4/)).
- **L3 Components** — только для ядра `createAsyncAiTask`, где решения неочевидны.
- **L4 Code** — намеренно не рисуем: этот уровень живёт в коде, дублировать его в
  документации противоречит принципу достаточности.

Каждая диаграмма показана в паре «как сейчас → целевая», чтобы видеть направление
изменения, а не только конечную картинку.
