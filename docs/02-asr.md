# 02 · Architecturally Significant Requirements (ASR)

Нефункциональные требования, которые определяют архитектуру. Каждое — измеримо и
защищается на ревью. Функциональные фичи здесь намеренно опущены.

## Атрибуты качества

### ASR-1 · Устойчивость к перезагрузке (Resilience)
Запущенная задача не теряется при перезагрузке страницы или падении вкладки.
После рестарта платформа восстанавливает активные задачи и продолжает их.
- **Сценарий:** пользователь запустил генерацию → обновил вкладку через 10 с →
  задача продолжает выполняться, результат приходит.
- **Метрика:** 100% активных задач восстанавливаются из хранилища при старте.

### ASR-2 · Гарантированное завершение (Correctness)
Каждая задача обязана прийти в терминальное состояние. «Вечных спиннеров» нет.
- **Сценарий:** бэкенд не ответил за отведённое время → задача переходит в
  `timeout` с видимым пользователю исходом (ошибка / повтор), а не исчезает молча.
- **Метрика:** доля задач без терминального состояния = 0.

### ASR-3 · Дешёвое добавление нового типа задачи (Modifiability)
Новый тип асинхронной задачи подключается конфигом, без копирования стейт-машины.
- **Сценарий:** добавить «AI-маршрут дня» → один конфиг + контракт ответа.
- **Метрика:** объём нового кода на тип задачи ≤ ~60 строк; стейт-машина не дублируется.

### ASR-4 · Единый транспортный контракт (Interoperability)
Long-poll и WebSocket работают через один и тот же job-контракт. Смена транспорта
не меняет доменную логику задачи.
- **Сценарий:** перевести генерацию блоков с poll на ws-push → правится только
  выбор адаптера, стейт-машина не трогается.

### ASR-5 · Корректность повторов (Reliability)
Ретраи и повторный запуск не создают дубликатов результата (идемпотентность по `job-id`).
- **Метрика:** при N повторах одной задачи в системе ровно один результат.

### ASR-6 · Наблюдаемость (Observability)
Переходы состояний и исходы задач логируются единообразно, независимо от типа и транспорта.

### ASR-7 · Эволюционируемость (Evolvability)
Клиентское хранилище состояния изолировано за портом, чтобы позже заменить его
серверным job-store без переписывания консьюмеров.

## Ограничения (constraints)

- **C-1:** frontend-only. Серверную часть и edge менять нельзя.
- **C-2:** стек — Effector + Farfetched + Runtypes (как в целевом модуле).
- **C-3:** единственное клиентское персистентное хранилище — localStorage.
