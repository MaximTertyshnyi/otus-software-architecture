# 03 · Атрибуты качества, trade-offs и сценарии

## Зачем нужны атрибуты качества

Функциональные требования говорят, **что** система делает; атрибуты качества —
**насколько хорошо** (устойчиво, изменяемо, надёжно…). Именно они формируют
архитектуру: почти любое архитектурное решение — это выбор в пользу одних атрибутов
ценой других. Фраза «хорошая архитектура» без указанных атрибутов бессмысленна —
хорошая *для чего*? Названные атрибуты делают качество **обсуждаемым и проверяемым**
(через сценарии), а не вкусовым.

## Каталог атрибутов

### Runtime — проявляются во время работы

| Атрибут | Кратко | Релевантность теме |
|---|---|---|
| Availability / Resilience | система/задача переживает сбои и восстанавливается | 🔴 приоритет |
| Reliability | корректный результат, без дублей и потерь | 🔴 приоритет |
| Performance | латентность и пропускная способность | 🟡 второстепенно |
| Scalability | поведение под ростом нагрузки | ⚪ н/д на клиенте |
| Security | контроль доступа, целостность | ⚪ решено платформой (auth) |
| Observability | видимость состояния и переходов | 🟡 поддерживающий |
| Usability | предсказуемость для пользователя | 🟡 через терминальные состояния |

### Времени разработки — проявляются при изменении и сопровождении

| Атрибут | Кратко | Релевантность теме |
|---|---|---|
| Modifiability | стоимость изменения / добавления фичи | 🔴 приоритет |
| Testability | лёгкость проверки поведения | 🟡 поддерживающий |
| Deployability | простота выката | ⚪ н/д на этом этапе |
| Reusability | переиспользуемость компонентов | 🟡 (порты/адаптеры) |

## Trade-offs между атрибутами

Атрибуты конфликтуют — усиление одного ослабляет другой. Ключевые компромиссы темы:

| Компромисс | Мы выбираем | Ценой | Где зафиксировано |
|---|---|---|---|
| Устойчивость ↔ простота | восстановление задач + персистентность | больше кода и состояния | [ADR-0003](adr/0003-task-state-store.md) |
| at-least-once ↔ отсутствие дублей | гарантию «≥1 раз» | обязательная идемпотентность по job-id | [ADR-0001](adr/0001-delivery-guarantees.md) |
| Изменяемость ↔ простота/производительность | порты + адаптеры (гексагон) | косвенность, риск «дырявой» абстракции | [ADR-0002](adr/0002-transport-port.md) |
| Единый транспорт ↔ точная модель push/pull | один job-контракт для poll и WS | нормализация двух разных потоков | [ADR-0002](adr/0002-transport-port.md) |
| Наблюдаемость ↔ шум | единый лог переходов | объём логов | ASR-6 |

Осознанно **депроритезируем**: Performance (задачи и так длятся секунды–минуты,
латентность опроса вторична), Security (авторизация уже решена платформой),
Scalability на клиенте (нагрузка ограничена одним пользователем).

## Приоритетные атрибуты нашей темы

Три атрибута, вокруг которых строится архитектура (остальные — поддерживающие):

1. **Устойчивость (Resilience / Availability).** Задача переживает reload и сбой
   вкладки. *Почему приоритет:* пользователь платит за долгую AI-генерацию; потеря
   задачи = потеря денег и доверия. Закрывает ASR-1, ASR-2.
2. **Изменяемость (Modifiability).** Новый тип задачи подключается без дублирования
   стейт-машины. *Почему приоритет:* сегодня каждый тип — это ~490 строк копипасты;
   это главная боль сопровождения. Закрывает ASR-3.
3. **Надёжность / корректность (Reliability).** Нет дублей результата, каждая
   задача приходит в терминальное состояние. *Почему приоритет:* at-least-once без
   идемпотентности = дубли; тихий дроп по таймауту = «вечный спиннер». Закрывает
   ASR-5 (и ASR-2 в части корректности).

## Сценарии качества (стимул → отклик)

Формат из 6 частей: **источник → стимул → артефакт → среда → отклик → мера отклика**.
Мера — то, что делает сценарий *проверяемым*.

### QAS-1 · Устойчивость (приоритет 1)

| Часть | Значение |
|---|---|
| Источник | пользователь / среда браузера |
| Стимул | перезагрузка вкладки во время активной AI-задачи |
| Артефакт | Task Orchestrator + Persistence port |
| Среда | нормальная работа, задача в статусе `processing` |
| Отклик | после рестарта платформа восстанавливает задачу из хранилища и продолжает опрос/подписку до терминального состояния |
| **Мера отклика** | 100% активных задач восстановлены; задача доходит до терминального состояния ≤ (дедлайн задачи + 1 интервал опроса); дубликатов результата = 0 |

### QAS-2 · Изменяемость (приоритет 2)

| Часть | Значение |
|---|---|
| Источник | разработчик |
| Стимул | нужно добавить новый тип AI-задачи |
| Артефакт | конфиг задачи + контракт ответа |
| Среда | время разработки |
| Отклик | тип подключается через `createAsyncAiTask`, стейт-машина не меняется |
| **Мера отклика** | ≤ ~60 строк нового кода; 0 строк дублирования стейт-машины; существующие типы задач не затронуты |

> **Результат модуля:** приоритетные атрибуты — устойчивость, изменяемость,
> надёжность; главный сценарий качества — **QAS-1** (устойчивость к перезагрузке
> с измеримой мерой отклика).
