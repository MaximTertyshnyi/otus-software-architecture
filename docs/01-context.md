# 01 · Контекст и границы

## Задача

В продукте есть несколько независимых механизмов, которые ждут результат
асинхронной AI-генерации:

- генерация «групп» на карте (long-polling);
- генерация AI-блоков/ответов (long-polling);
- чат с ассистентом (WebSocket через Centrifugo).

Первые два — почти идентичные стейт-машины (~490 строк каждая) поверх общей очереди
`polling_queue`; третий — отдельный движок. Общей модели асинхронной задачи нет.

**Цель проекта** — спроектировать единую клиентскую платформу оркестрации
асинхронных задач: одна job-модель, гарантии доставки, сменный транспорт,
явные терминальные состояния.

## Границы системы (scope)

**В границах проекта (строим и демонстрируем, всё на клиенте):**

- job-модель и стейт-машина задачи;
- планировщик опроса (backoff + jitter, конфигурируемый);
- `Transport port` + адаптеры long-poll и WebSocket;
- `Persistence port` + адаптер localStorage (с валидацией схемы);
- прогресс и терминальные состояния.

**Вне границ (фиксируется в ADR как вектор эволюции, не реализуется):**

- серверный job-store и серверный планировщик;
- серверный дедуп / exactly-once;
- изменения бэкенд-контрактов и edge-инфраструктуры.

Причина: проект ведётся в frontend-only режиме — серверная часть недоступна для
изменения. Переход «клиентский store → серверный job-сервис» описан решением
([ADR-0003](adr/0003-task-state-store.md)), а не кодом.

## Внешние зависимости (акторы и системы)

| Актор / система | Роль |
|---|---|
| Пользователь | инициирует AI-задачи, ждёт результат |
| Backend генерации (группы/блоки) | `POST …/collect` (старт) → `GET <uri>` (опрос статуса) |
| Centrifugo | WebSocket pub/sub для чата |
| localStorage браузера | клиентское хранилище состояния задач |

## Глоссарий

| Термин | Значение |
|---|---|
| **Задача (job)** | единица асинхронной работы с уникальным `job-id` и жизненным циклом |
| **Транспорт** | способ получить результат: long-poll (опрос) или ws-push (подписка) |
| **Терминальное состояние** | `done` \| `failed` \| `timeout` \| `canceled` — состояние, из которого нет переходов |
| **Клиентский таймаут** | защитный порог «если что-то не так»: генерация 7 мин (`POLLING_UPPER_LIMIT`), чат 180 с (`fallback_config.timeout_seconds`). Не SLA нормальной длительности — задача обычно завершается кратно быстрее |
| **at-least-once** | гарантия, что задача будет выполнена ≥ 1 раза (возможны повторы → нужна идемпотентность) |
| **Идемпотентность по job-id** | повторный запуск с тем же `job-id` не создаёт дубликат результата |
| **backoff** | нарастающий интервал между опросами; **jitter** — случайный разброс, чтобы избежать синхронных всплесков |
